# Dynamic Resource Allocation

DRA lets workloads request devices through `ResourceClaim` and `ResourceClaimTemplate` objects. KAI supports DRA through the binder, which coordinates the scheduler decision with device allocation state by using `BindRequest`.

<BinderDraAnimation />

Display the full GPU DRA manifest.

```bash
cat manifests/20-dra/dra-full-gpu.yaml
```

Apply the DRA workload.

```bash
kubectl apply -f manifests/20-dra/dra-full-gpu.yaml
```

List ResourceClaimTemplates.

```bash
kubectl get resourceclaimtemplates -n kai-lab20
```

List ResourceClaims. These are generated for Pods that reference the template.

```bash
kubectl get resourceclaims -n kai-lab20
```

List DeviceClasses. fake-gpu-operator and the DRA driver surface device classes for scheduling.

```bash
kubectl get deviceclasses
```

Inspect the Pod claim section.

```bash
kubectl describe pod -n kai-lab20 dra-full-gpu | sed -n '/Resource Claims:/,/Events:/p'
```

Display the ComputeDomain snippet. This is a reference-only example for GB200/GB300-style IMEX channel allocation.

```bash
cat manifests/20-dra/compute-domain-snippet.yaml
```

## Clean Up

Delete the DRA namespace. This removes the Pod, ResourceClaimTemplate, and generated ResourceClaim.

```bash
kubectl delete namespace kai-lab20 --ignore-not-found
```

## What Just Happened

You used the DRA path end to end: claim template, claim, Pod reference, and binder coordination. The ComputeDomain snippet shows how multi-node GPU fabrics can be modeled, but the fake GPU lab intentionally does not deploy real IMEX devices.

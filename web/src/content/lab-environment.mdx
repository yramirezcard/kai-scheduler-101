# Lab Environment

This lab runs on a CPU-only Brev VM, but it gives KAI a realistic GPU-shaped Kubernetes environment to schedule against. The Kubernetes distribution is **K3s**, a lightweight distribution that is well suited for a single-VM hands-on lab. K3s provides the real Kubernetes API server, controller manager, scheduler, kubelet, and storage/networking basics.

Because the VM does not have physical GPUs or many real worker machines, the lab uses **KWOK** to simulate multiple Kubernetes Nodes. Those fake Nodes behave like schedulable cluster capacity from the API server's point of view, which lets the later topology, placement, and queue examples reason about more than one node.

The lab also installs **fake-gpu-operator** to simulate GPU devices on those KWOK-managed Nodes. It exposes fake GPU capacity and DRA objects so workloads can request GPUs through Kubernetes APIs without needing real accelerators.

KAI Scheduler is not installed yet. You will install it as part of the lab, then inspect how KAI uses queues, PodGroups, priorities, DRA claims, and simulated GPU capacity to make scheduling decisions.

Before installing KAI, inspect the cluster you have been given. The point of this chapter is to separate the base Kubernetes environment from the KAI control plane you will install later.

The first command confirms that `kubectl` can reach the k3s API server.

```bash
kubectl cluster-info
```

List all nodes with extra detail. You should see the k3s control-plane node plus KWOK-managed simulated nodes.

```bash
kubectl get nodes -o wide
```

Observe the count of KWOK nodes. Four fake GPU nodes are enough for the first half of the lab; a later topology chapter expands the fleet to 24 nodes.

```bash
kubectl get nodes -l type=kwok
```

The Lab uses GPU DRA Driver, there GPUs are exposed through ResourceSlice objects. Inspect how many GPUs are available per node with the following query.

```
kubectl get resourceslices -o json \
  | jq -r '
      ["NODE","GPUS"],
      (
        [.items[]
          | select(.spec.driver == "gpu.nvidia.com")
          | {
              node: .spec.nodeName,
              gpus: (.spec.devices // [] | length)
            }
        ]
        | group_by(.node)[]
        | [.[0].node, (map(.gpus) | add)]
      )
      | @tsv
    ' \
  | column -t
```


List every Pod in the cluster. At this point you are looking for Kubernetes and simulation components, not KAI.

```bash
kubectl get pods -A
```


## What Just Happened

You verified a real Kubernetes API, Helm, the default scheduler, and the fake GPU node pool. The lab is intentionally CPU-only, but the scheduler sees a GPU-shaped cluster. That lets you focus on KAI scheduling behavior without waiting for physical GPU capacity.

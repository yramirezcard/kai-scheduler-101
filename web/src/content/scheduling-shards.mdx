# Scheduling Shards

Scheduling shards partition a cluster into independent scheduling domains. Each shard can have its own scheduler deployment, node set, queue set, PodGroups, and scheduler arguments.

<ShardAnimation />

Start by inspecting the four KWOK nodes created during setup. The lab already labels two nodes as H100 and two nodes as L40S, so this chapter reuses the existing simulated cluster instead of creating new nodes.

```bash
kubectl get nodes -L nvidia.com/gpu.machine
```

List nodes that match the simulated H100 label.

```bash
kubectl get nodes -l nvidia.com/gpu.machine=NVIDIA-DGX-H100
```

List nodes that match the simulated L40S label.

```bash
kubectl get nodes -l nvidia.com/gpu.machine=NVIDIA-L40S
```

Display the H100 shard manifest. This shard targets nodes, queues, and PodGroups labeled `nvidia.com/gpu.machine: NVIDIA-DGX-H100`. Creating it causes KAI to reconcile a scheduler deployment for the H100 partition.

```bash
cat manifests/17-shards/scheduling-shard-h100.yaml
```

Apply the H100 shard.

```bash
kubectl apply -f manifests/17-shards/scheduling-shard-h100.yaml
```

Display the L40S shard manifest. It targets a different node set and uses a smaller action set to show that shards can carry different scheduler arguments.

```bash
cat manifests/17-shards/scheduling-shard-l40s.yaml
```

Apply the L40S shard.

```bash
kubectl apply -f manifests/17-shards/scheduling-shard-l40s.yaml
```

List scheduler deployments. Each shard gets its own scheduler deployment and therefore its own scheduling cycle over the matching partition.

```bash
kubectl get deployments -n kai-scheduler
```

Read the H100 shard resource.

```bash
kubectl get schedulingshard h100-shard -o yaml
```

Read the L40S shard resource.

```bash
kubectl get schedulingshard l40s-shard -o yaml
```

Display the H100 workload. Its queue and Job labels match the H100 shard partition.

```bash
cat manifests/17-shards/h100-workload.yaml
```

Apply the H100 workload.

```bash
kubectl apply -f manifests/17-shards/h100-workload.yaml
```

List H100 Pods and confirm they are placed only on the H100 node set.

```bash
kubectl get pods -n kai-lab17-h100 -o wide
```

Inspect the H100 shard scheduler logs after deploying the H100 workload. This log stream belongs to the scheduler deployment for the H100 shard.

```bash
kubectl logs -n kai-scheduler deployment/kai-scheduler-h100-shard --tail=120
```

Display the L40S workload. Its queue and Job labels match the L40S shard partition.

```bash
cat manifests/17-shards/l40s-workload.yaml
```

Apply the L40S workload.

```bash
kubectl apply -f manifests/17-shards/l40s-workload.yaml
```

List L40S Pods and confirm they are placed only on the L40S node set.

```bash
kubectl get pods -n kai-lab17-l40s -o wide
```

Inspect the L40S shard scheduler logs after deploying the L40S workload. This log stream belongs to the scheduler deployment for the L40S shard.

```bash
kubectl logs -n kai-scheduler deployment/kai-scheduler-l40s-shard --tail=120
```

## Clean Up

Delete both shard examples before moving on.

```bash
kubectl delete schedulingshard h100-shard l40s-shard --ignore-not-found
```

Delete the workload namespaces.

```bash
kubectl delete namespace kai-lab17-h100 kai-lab17-l40s --ignore-not-found
```

Delete the shard-specific queues.

```bash
kubectl delete queue h100-research l40s-inference --ignore-not-found
```

## What Just Happened

You created two node-pool-specific scheduler configurations over the four existing KWOK nodes. The H100 shard watched the two H100-labeled nodes, queues, and workloads; the L40S shard watched the two L40S-labeled nodes, queues, and workloads. That isolation is the main value of shards: each shard gets its own scheduler deployment, scheduling cycle, node partition, queue labels, workload labels, and action configuration.

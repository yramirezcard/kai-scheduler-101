# Priority Classes

Queue priority and workload priority are different systems. Queue priority controls surplus distribution between queues. Workload priority controls ordering and preemption inside one queue.

The `priorityClassName` on a workload controls three things:

- `Scheduling order` — higher-priority workloads are scheduled first when resources become available

- `Preemptibility` — by default, priority < 100 is preemptible, priority >= 100 is non-preemptible

- `Preemption` — a higher-priority workload can evict a lower-priority preemptible workload to free up resources, but only within the same queue


KAI includes conventional priority values for common AI workload types. The important threshold is 100: workloads with priority value 100 or higher are treated as non-preemptible and can only consume in-quota resources.

Display the PriorityClass manifest.

```bash
cat manifests/10-priority/priority-classes.yaml
```

Apply the priority classes. The command is idempotent, so it is safe if KAI already created matching classes.

```bash
kubectl apply -f manifests/10-priority/priority-classes.yaml
```

List the four classes used by the lab.

```bash
kubectl get priorityclass train build-preemptible build inference
```

Read the `train` priority value.

```bash
kubectl get priorityclass train -o yaml
```

Read the `inference` priority value and compare it with `train`.

```bash
kubectl get priorityclass inference -o yaml
```
